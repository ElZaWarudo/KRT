# Summarization Policy

Use this policy when creating compact harness-ready summaries from Markdown generated by `krt-document-forge`.

## Artifact Layout

Keep both layers:

```text
docs/harnesses/
├── sources/
│   └── <base>.md
└── summaries/
    └── <base>.md
```

Models and harness workflows should read `summaries/<base>.md` first. Use `sources/<base>.md` only when the summary marks uncertainty, a required detail is missing, or exact wording is needed.

## Frontmatter

Every summary must start with:

```yaml
---
summary_type: harness-ready
source_path: ../sources/<base>.md
source_sha256: "<sha256 of source markdown>"
source_fallback_policy: "Use this source only if the summary marks uncertainty, a required detail is missing, or direct wording is needed."
generated_by: krt-document-forge
updated: YYYY-MM-DD
---
```

Use a relative `source_path` from the summary file to the source Markdown file.

## Required Sections

```markdown
# <Document Title>

## Purpose
## Agent-Ready Facts
## Requirements And Constraints
## Decisions And Assumptions
## Risks And Open Questions
## Figures And Tables
## Fallback Source
```

`Fallback Source` must include a Markdown link to the source:

```markdown
- Source: [<base>.md](../sources/<base>.md)
```

## Writing Rules

- Keep the summary short enough for a model to read by default.
- Prefer implementation-relevant facts over narrative background.
- Preserve names, identifiers, dates, constraints, and acceptance criteria exactly when they matter.
- Do not invent requirements, decisions, or certainty that the source does not support.
- Mark uncertainty in `Risks And Open Questions`.
- Reference tables and figures by source section, table caption, image link, or nearby heading when they may matter.
- Avoid duplicating long tables; summarize their purpose and tell the model when to inspect the source.
