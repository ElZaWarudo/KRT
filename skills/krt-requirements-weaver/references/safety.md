# Safety Model

`krt-requirements-weaver` clarifies requirements before planning or coding.
Its main risk is false certainty.

- Stay at the requirements level: no architecture, schema, code or task
  planning unless the user asks for solution design.
- Do not invent functional or non-functional requirements. Supplied measures,
  standards and regulations are marked as proposals to confirm.
- Keep material gaps visible as open questions; never hide them behind
  assumptions.
- Functional requirements that will be built carry acceptance criteria.
- Keep requirements traceable to the source text and its stakeholders.
