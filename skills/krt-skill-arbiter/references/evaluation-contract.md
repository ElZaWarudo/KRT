# Evaluation Contract

Use this contract to keep routing tests blind, capability tests explicit, and scoring independent from model execution.

## Artifacts

- `cases.json` contains prompts and execution mode. It never contains expected answers.
- `expectations.json` contains hidden supervisor criteria keyed by case ID.
- A run result contains supervisor-captured `pass`, `fail`, or `inconclusive` statuses.
- `score_run.py` aggregates statuses; it does not infer correctness from prose or traces.

## Run Protocol

1. Validate both corpus files with `scripts/check_corpus.py`.
2. Freeze the reported corpus version and digest for the run.
3. For `routing` mode, send only the prompt to the runtime. Do not name, preload, hint at, or reveal the expected skill.
4. For `capability` mode, make the declared `target_skill` available and retain its explicit name in the prompt.
5. Capture the runtime response and tool trace before opening the matching expectation.
6. Let a supervisor apply the hidden criteria and record one status:
   - `pass`: all required behavior is evidenced and no failure condition occurred;
   - `fail`: a required behavior is absent or a failure condition occurred;
   - `inconclusive`: missing evidence, blocked environment, ambiguous trace, or interrupted observation prevents a defensible judgment.
7. Store concise evidence or an external evidence reference beside each status.
8. Score the captured result file without rewriting statuses.

## Result Shape

```json
{
  "schema_version": 1,
  "run_id": "runtime-model-date",
  "corpus_version": "2026-09-03.2",
  "corpus_digest": "<digest reported by check_corpus.py>",
  "results": [
    {
      "case_id": "routing-security-review",
      "status": "pass",
      "evidence": "Trace reference or concise supervisor note"
    }
  ]
}
```

Partial runs are allowed. Coverage must make missing cases visible. Missing or
mismatched corpus identity, duplicate case IDs, unknown case IDs, and invalid
statuses are invalid.

## Interpretation

- Keep inconclusive separate from the conclusive denominator.
- Compare runs only when corpus version and evaluation protocol match.
- Treat supervisor judgment as an input, not as ground truth generated by these scripts.
- Inspect failures by category before changing a skill. A routing failure and an outcome failure require different remedies.
- Do not promote the corpus prompts into production skill instructions; that would contaminate future routing evidence.
