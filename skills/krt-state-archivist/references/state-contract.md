# Compact State Contract

Use this reference when compacting `compound-master-state.md`, reviewing a scaffold generated by `compact_compound_state.py`, or applying the same live-context split to explicit Compound Master instruction entrypoints.

## Purpose

The live state file is a resume entrypoint, not the whole project journal. It should tell the next agent what is true now, where the canonical artifacts live, what is blocked, and what to do next.

The archive holds the full historical record: old verification logs, review rounds, Jira/PR closeouts, merged phase details, repeated brainstorm decisions, and long evidence sections.


The same contract applies to Compound Master instruction compaction: the live `SKILL.md` or router document is an entrypoint, not the whole operating manual. It should route the model to the right reference and keep only universal hard rules in immediate context. Phase-specific detail should live in the reference loaded by that phase.

## Live Instruction Entrypoint Must Keep

- Purpose, arguments, and invocation modes.
- Progressive-loading or reference-routing table.
- Core pipeline skeleton and phase boundaries.
- Universal non-negotiable rules that apply in every phase.
- Stop/closeout discipline.
- Links to phase references that now own moved detail.

## Instruction References Should Receive

- PR, Jira, reviewer, and release-handoff details.
- Execution, delegation, impact-scan, review, security, and CI details.
- Autonomous-mode ledgers, mutation classes, validators, and enforcement detail.
- Edge-case rules that apply only inside one phase.
- Anti-patterns and checker-trust rules next to the action they prevent.

## Live State Must Keep

- Initiative, status, mode, date, and production posture when known.
- Source documents and canonical artifact paths.
- Current phase, active work package, and package wave.
- Current branch, integration base, parent branch/stacking strategy, and open PR/Jira items.
- Current blockers or "No blockers".
- Required user decisions.
- Next action and exact next invocation when one exists.
- Links to archived history.
- Any active risk that has not been resolved in a linked artifact.

When the script detects a latest `Phase N` or `Fase N`, scaffolded operating state must be biased toward that latest-phase window. Older branch strategies, PRs, Jira statuses, blockers, and review notes are historical unless the latest phase repeats them or the agent verifies them against current repo/GitHub/Jira state.

## Archive Should Receive

- Completed phases and packages.
- Long verification command/result lists.
- Historical review findings that are resolved.
- Merged PR details and closed Jira handoff details.
- Old branch strategies that no longer affect the next action.
- Repeated decisions already captured in brainstorm, plan, or work-package documents.
- CI evidence for completed packages, unless a CI incident remains active.

## Compact State Shape

Prefer this shape:

```markdown
---
title: Compound Master State - <initiative>
status: in_progress
date: YYYY-MM-DD
initiative: <slug>
mode: resume
state_format: compact
last_compacted: YYYY-MM-DD
archive_snapshot: docs/orchestration/archive/compound-master-state/...
---

# Compound Master State - <initiative>

## Resume Snapshot
- Current phase/status:
- Active package:
- Branch/base:
- Open PR/Jira:
- Blockers:
- Next action:

## Source Documents
- ...

## Current Operating State
- ...

## Required Decisions
- ...

## Archived History
- Full pre-compaction state: `...`
- Historical sections: ...
```

The exact headings can vary, but the live state must stay easy to scan before resuming work.

## Review Checklist

- The compact file points to the full archive.
- The archive was created before the live state was rewritten.
- No active blocker was archived as historical.
- The next action is explicit enough for `krt-compound-master mode:resume`.
- PR/Jira status reflects open work, not old closeouts.
- `Active Signals To Review` does not mix contradictory phase signals without an explicit `CURATION REQUIRED` warning.
- The compact file is materially shorter than the original.
